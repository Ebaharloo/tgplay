## 1. Verdict

1. The wiring fixes in this tree are real: skip now probes direct/HLS streams,
   the MAL id is passed to the playlist, `'off'` survives as an explicit skip
   choice, and no widget reads `isVisible()` to decide a value any more.
2. Two features are still not wired end-to-end: **AnimeX server choice from the
   Options panel is thrown away on play**, and **`--next` prefetch downloads
   bytes that playback never reads** (`RangeProxy.set_local` has no caller).
3. One state-loss bug class remains everywhere: every `~/.config/tgp/*.json` is
   written with `json.dump(open(p,'w'))` — `progress.json` is rewritten every
   3 s during playback, so a crash mid-write loses *all* resume positions.
4. The Cast cache is written **before** the Bangumi/Fandom merge, so every
   cached open (30-day TTL) silently drops the CN + wiki rosters the feature
   exists for.
5. Dead code is small and easy to drop (`LogView`, 8 unused functions); the
   rest is duplication that has already diverged (`_GENERIC` vs `_GENERIC_EP`,
   `recent.json` vs `history.json`).

## 3. Findings

### P0

**1. `progress.json` is truncated-rewrite, every 3 s — total loss of resume data.**
`tp/playlist.py:57-61`
Trigger: any crash / power loss / `SIGKILL` while an episode plays (the file is
rewritten by `PosWatcher._tick` every `interval`, default 3 s,
`playlist.py:167-172`).
Symptom: `progress.json` is half-written → next start `_load()` returns `{}` →
**every** show's resume position is gone (not just the current one). Same window
also makes `Session.status()` (`session.py:162-172`) return `'idle'` for a tick.
Fix: write `tmp = path + '.tmp'; json.dump(...); os.replace(tmp, path)` (and the
same in `history._save`, `setup.save`, `metadata._write`, `simkl_account._write`,
`characters._put`, `ui.recent_add`).

**2. AnimeX server/quality picked in the Options panel is discarded on play.**
`tp/session.py:113-116` + `tp/providers/animex.py:295-303`
Trigger: open an AnimeX show, change **Server** (or Quality) in the panel, press
Play.
Symptom: `Session.play` calls `provider.select(o['f'])` (good) and then
`set_audio()`, which clears `_chosen`/`_loaded`; `episodes()` → `load()` →
`select(self.quality)` where `self.quality` is the value captured at
`open_session` time. The new server is written to `ui.json` (`session.py:106`)
and only takes effect the *next* time the show is loaded. Audio changes do work
(`_resolve_audio` runs after `set_audio`).
Fix: in `set_audio` keep `_chosen`/the picked `_pref` (only re-resolve audio), or
have `Session.play` call `select()` **after** `set_audio()` — and set
`self.quality = quality` inside `select()`.

### P1

**3. `--next` prefetch has no consumer: the disk mirror is never registered.**
`tp/proxy.py:68-75` (`set_local`), `tp/playlist.py:117-127`, `tp/cache.py:121`
Trigger: enable "next ep" / `--next`, play an episode.
Symptom: logs `next: prefetching ep N` + `download: … MB in Xs`, `/tmp/agp-cache`
fills up — and the next episode still streams from the network, because the
playlist only ever hands mpv `proxy.url(name)` and nobody calls
`set_local(name, cache.path(name), size, lo)`. `Prefetcher.cancel` is never
called either, so the "cancellable" claim does not hold, and `Cache.evict`
(and therefore `Config.cache_budget`) is never enforced — `/tmp` grows until a
manual `agp cache clean`.
Fix: after `register()` in `playlist.run`, if `cache.is_full(name)` call
`proxy.set_local(...)`, and call `prefetcher.cancel(name)` when the episode
starts; call `cache.evict(keep=[name])` after each episode.

**4. Cast cache is written before Bangumi/Fandom rows are merged.**
`tp/characters.py:336` (write) vs `:173-176` (merge)
Trigger: open Cast twice for the same show (second open = cache hit).
Symptom: first open shows the deep cast (anime + manga/novel + CN + wiki, e.g.
Renegade Immortal ~274 rows); every later open for 30 days shows only the
AniList rows, because `_anilist()` persisted `rec` before `_boost`/`_merge_wiki`
appended to the same dict.
Fix: move `_put()` to the end of `fetch()`.

**5. AniList tracking is silently off when the token comes from the env.**
`tp/tracking.py:44-51` (`enabled()` reads only `anilist.json`) vs
`tp/status.py:80-84` (green light for `AGP_ANILIST_TOKEN`)
Trigger: `export AGP_ANILIST_TOKEN=…`, finish an episode.
Symptom: `MultiTracker.mark_watched` skips the AniList tracker
(`tracking.py:322`), no error, light still green; CLI `agp sync` *does* work
(`sync()` checks `not self.enabled() and not self.token()`), so the two paths
disagree.
Fix: `enabled()` → `return bool(self.token()) and a.get('enabled', True)` minus
the `AGP_NO_TRACK` check it already has.

**6. Closing the window during playback orphans mpv and drops progress.**
`tp/gui_all.py:2180-2204`
Trigger: press **Close** (or the window X) while an episode plays.
Symptom: `close_window` stops the timers, closes the proxy and calls
`QApplication.quit()`; it never calls `session.stop()` and never joins the play
thread. The daemon playlist thread dies with the process, mpv keeps playing with
no window/IPC, the last position is never written. If the old playlist thread is
mid-loop, `session.close()` has also already shut the proxy it is streaming from.
Fix: `self.state['session'].stop()` before `close()`, and refuse/confirm close
while `state['playing']`.

**7. Missing/broken mpv is reported as a normal run over the whole list.**
`tp/player.py:88-90` returns `1`; `tp/playlist.py:203-232` only special-cases
`4` (quit) and `2` (open failure).
Trigger: mpv not installed / not executable, or mpv fails to spawn.
Symptom: every episode logs `>> streaming epN: …` and then nothing happens;
the playlist walks all selected episodes in a second and prints `>> done`.
Fix: treat `rc in (1, -1)` from `Popen` failure as fatal (log + `return`), e.g.
have `Player.play` raise or return `None` and bail in `run()`.

**8. Every run rewrites the remembered setup, including non-interactive CLI.**
`tp/session.py:104-108` vs `tp/setup.py:1-6` ("Only the *menu* uses this").
Trigger: `agp <url> -q 480 --cut 20` (no menu), then open the GUI.
Symptom: `ui.json` for `agp` now holds the ad-hoc CLI values; the GUI comes up
with a different quality/cut than the user last chose in the form.
Fix: save from the menu paths only (`cli.py:346`, `cli_animex.py:137`,
`cli_telegram.py:165`) and drop the save from `Session.play`.

### P2

**9. `--skip=off` on the command line silently becomes skip `all`.**
`tp/cli.py:176-178` — `m if m in ('all','names','auto') else 'all'`.
Trigger: `agp <url> --skip=off`.
Symptom: intro/outro are skipped although the user asked for none. (The GUI and
`tp.options` now support `'off'`; only `parse()` doesn't.)
Fix: include `'off'` in the accepted set.

**10. Poisoned `head_warm`: the skip probe is fired at a proxy that may 503.**
`tp/proxy.py:102-106` sets the wait event in `finally`, even when the head fetch
raised; `playlist.py:123-127` treats a set event as "head ready" and passes the
proxy URL to `ffprobe`.
Trigger: CDN blip on the first 8 MB.
Symptom: 6 s `ffprobe` timeout per episode (`skip: failed/… in 6.0s`) and no
chapters, instead of ani-skip.
Fix: set the event on success only, plus a separate `head_ok` flag the playlist
reads.

**11. `Session.resume` is a load-time snapshot.**
`tp/session.py:87,132`
Trigger: watch ep 1 to the end in the window, then press Play on ep 1 again.
Symptom: it seeks to the position saved when the window loaded the show (or 0),
not to "finished"; the marker in the title/status also lags.
Fix: re-read `_resume(cfg, title)` in `play()` before computing `start`.

**12. Loading another show while an episode plays cuts the stream.**
`tp/gui_all.py:1339-1345` → `old.close()` → `RangeProxy.stop()`.
Trigger: click a search result while a video plays.
Symptom: the playing mpv loses its byte source (frozen video), while the old
playlist thread keeps retrying/registering on a stopped proxy; no message.
Fix: `old.stop()` + refuse the load (or confirm) while `state['playing']`.

**13. Stop does not clear the `playing` guard promptly.**
`tp/gui_all.py:1330-1337`; `playlist.py:194` `watcher.join(timeout=12)`.
Trigger: Stop, then immediately press another Play.
Symptom: the click is silently ignored for up to ~12 s (mpv 0.41 exits `4` on
SIGTERM — verified — so the loop itself does return, it just waits on the
watcher).
Fix: reset `state['playing']=False` in the playlist's `on_done`/finally and
shorten the join.

**14. `SimklTracker` hard-codes Simkl season 1.**
`tp/simkl_account.py:308-310`
Trigger: sync a show that Simkl stores as season 2/3 (AniDB numbering).
Symptom: progress lands on the wrong season or is ignored; already listed as a
known gap in FEATURES.md, but it is a silent wrong write, not just a missing
feature.
Fix: send `{'number': <season from the library row>}` or omit `seasons`.

**15. `SimklTracker` logs "already watched" when it had no ids at all.**
`tp/simkl_account.py:369-385` + `mark_watched` `:306-307`.
Trigger: a title matched only by name, with no mal/anilist/simkl id.
Symptom: `simkl: ep N already watched — …` for a show that was never synced.
Fix: return a distinct `None` and log "no ids to sync".

**16. `main_all` rejects a bare search term typed on the command line.**

Symptom: `tgplay: could not tell the source of "naruto"` + full help, exit 2 —

**17. Search results can be applied out of order.**
`tp/gui_all.py:1496-1507` (one worker per keystroke pause) +
`tp/gui_all.py:1572-1577` (one queue item per 150 ms tick).

**18. History view de-duplicates by title only.**
`tp/gui_all.py:1630-1638` (comment even says "same link can appear once per

**19. Two independent "recent" stores.**

**20. `ui.pick_start` plain fallback: `a` does not mean "all".**
`tp/ui.py:189-195` — `if v in ('', 'a'): start = resume…`, then returns
"from start"; the prompt and the curses screen both say `a = all`.
Trigger: no curses (piped/dumb terminal), answer `a`.
Symptom: plays from the resume episode instead of the whole list.

**21. The curses form falls back to plain `input()` on any exception.**
`tp/ui.py:272-277` swallows every error from `_curses_form` and calls
`_plain_form`, which blocks on stdin and asks only quality/audio/eps/cut.
Trigger: any bug in the form rendering, or a terminal that curses half-likes.
Symptom: the user's skip/next/fullscreen choices are never offered; in a GUI-ish

**22. `_fetch_calendar` swallows every failure as "no upcoming episodes".**
`tp/library.py:28-35`.
Trigger: Simkl calendar endpoint down / token issue.
Symptom: the Calendar filter renders "nothing here" with no reason (the GUI only

**23. MAL scraping depends on the `curl` binary, unchecked.**
`tp/metadata.py:151-157`, used by `_mal_search`/`_mal_titles`.
Trigger: `curl` absent (flatpak/minimal install).
Symptom: `FileNotFoundError` → the `mal` circuit breaker trips for 15 min →

**24. `resolve_mal` always spends an AniList round-trip before asking MAL.**
`tp/metadata.py:192-217`.
Trigger: every show load with no cached MAL id (`session.py:175-185,289`).

**25. Cast refresh ignores its own TTL, every open.**

**26. `_anilist` requests page 1 twice.**
`tp/characters.py:293-294` then `:302-308` (loop starts at page 1 again).

**27. `AnimeXProvider._m3u8_quality` leaks the HTTP response.**

**28. `SimklTracker._match` accepts a 0.55 fuzzy match.**

**29. Multi-thread dict/set state without locks.**
`tp/proxy.py:51` `RangeProxy.streams` (playlist thread writes, HTTP handler

## 5. What I could not verify statically

- **Real CDN / API behaviour**: whether AnimeGate's `/global-search`, AnimeX's
  `servers`/`sources` payloads and Simkl's `/sync/all-items` still match the
  parsers (`animegate.parse_page`, `animex._find_anime`, `simkl_account._norm`).
  Every one of those is wrapped in a broad `except` that turns a shape change
  into "no results", so a live probe per endpoint is the only proof.
- **`mpv` exit codes beyond `0/2/4`.** I did verify locally that mpv 0.41 returns
  `4` on SIGTERM (so the Stop button does reach the "user quit" branch); `-9`
  (OOM killer / `kill -9`) would still fall through to "episode finished" and
  auto-advance (`playlist.py:203-232`).
- **Whether a prefetch would actually be picked up if `set_local` were called** —
  name identity between `Playlist._name()` and the prefetch call is the same
  function, so it should be; not exercised end to end.
- **Simkl season mapping** and whether `add_to_list` / `sync/history` accept the
  `{'mal': …}` ids alone — needs an account.
- **AnimeX server ids** (`nero`, …) and whether a panel change would actually
  stream differently — the logic bug is certain, the user-visible delta is not
  tested.
